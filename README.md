# Olist 订单履约分析与延迟预警方案

基于 Olist 公开数据的个人项目。分析订单逾期与低评分的关联，并据此设计订单延迟预警与客户通知流程。独立完成从数据分析到需求方案落地的全流程。

## 需求分析

**业务背景。** 逾期与低评分的关联提示履约延迟值得关注。我据此提出一个待验证的业务问题：在订单可能晚到时，能否让运营提前识别风险、核实信息，帮助客户及时了解预计送达时间？

**方案设计。** 运营根据风险原因、物流轨迹和通知历史，决定发送或暂缓复查。发送前校验订单状态、通知偏好和历史记录，减少误发及重复发送。客户从通知进入订单页，查询最新预计送达日期。

**案例 · ORD-8742**　运营先通知客户预计 **3 月 20 日**送达。后来预测更新为 **3 月 22 日**，第二次通知尚未发送。客户端的通知原文仍保留 3 月 20 日，订单状态页已显示 3 月 22 日。两处日期分别对应已发通知和最新预测。

## 数据分析

**数据与方法。** 使用订单、评价、客户三张表。用 MySQL 核验并归并为一单一行，用 Python 计算履约、低评分和州别指标，再通过月度 SQL 结果核对 Power BI 看板。逾期率以有效履约订单为分母，低评分定义为 1～2 分。

| 分析角度 | 关键发现 | 数据依据 |
| --- | --- | --- |
| 整体履约 | 核验 **99,441 笔**订单。**96,470 笔**有效履约订单中 **6,534 笔**逾期，逾期率为 **6.77%**。 | [履约汇总](data-analysis/tables/fulfillment-summary.csv) |
| 评价时点 | 有评价的有效履约订单中，逾期组与准时组低评分率为 **62.36% 对 9.26%**。仅保留收货后评价时，为 **19.42% 对 9.24%**，组间差距由 **53.10** 缩至 **10.18** 个百分点。 | [样本对照](data-analysis/tables/late-delivery-and-ratings.csv) |
| 州别差异 | 圣保罗州（SP）逾期率为 **4.49%**，占样本全部逾期订单的 **27.85%**。里约热内卢州（RJ）逾期率为 **12.11%**。逾期率和逾期单量分别反映风险比例和问题规模。 | [州别汇总](data-analysis/tables/state-summary.csv) |
| 履约阶段 | 审批、处理、运输阶段耗时的第 90 百分位（P90）分别为 **1.44、6.02、18.90 天**。运输阶段指从交承运商到客户签收。 | [阶段耗时](data-analysis/tables/fulfillment-stage-duration.csv) |

**[查看 Power BI 看板 PDF（2 页）](data-analysis/olist-delivery-dashboard.pdf)**

看板支持下单月份、收货州、逾期状态多维度筛选，可定位不同场景下的履约延迟与低评分特征。第 1 页展示履约与低评分监控，以及下单月份、客户收货州和是否逾期三个筛选器。第 2 页展示 SQL04 月度核对。PDF 为静态预览，筛选器和表格滚动需在 Power BI Desktop 中操作。

这些结果反映历史样本中的统计关联。评价时点会改变纳入分析的订单构成，比较时应同时看筛选条件和分母。[Olist 数据来源](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)
